# 野々村病院の人々 (NONOXP, AI5WIN 2003) — 포맷 분석 노트

## ARC (Mes/Data/Bg/Music/Voice)
- u32 개수, 이어서 28바이트 엔트리: 이름[20] + size^0x15056109 + offset^0x32300645
- 5개 아카이브 모두 같은 키. `tools/arc.py`

## MES / LIB (스크립트)
- 아카이브 안에서 LZSS(4096 창, 시작 0xFEE, 플래그 LSB 우선, 1=리터럴)
- 풀면: u32 라벨 수 N, u32 라벨 오프셋[N](코드 시작 기준), 코드
- 문장 명령(1바이트):
  00 END | 01 TXT sjis\0 | 02 STR ascii\0 | 03 SETRBC u16,exprs | 04 SETV u8,exprs
  05 SETRBE expr,exprs | 06 SETAC expr,u8,exprs | 07 SETA@ expr,u8,exprs | 08 SETAD expr,u8,exprs
  09 SETM32C u16,exprs | 0A SETM32E expr,exprs | 0B JZ expr,u32 | 0C JMP u32 | 0D SYS expr,params
  0E GOTO params | 0F CALL params | 10 MENUI params,u32 | 11 PROC params | 12 UTIL params
  13 LINE u8 | 14 PROCD expr,u32 | 15 MENUS params | 16 SETRD u8,exprs | 17 MSGID u32
  18 JMPLBL expr | 19 (인자 없음) | 1A (인자 없음) | 1B params | 1C LIBDEF expr,u32
  1D LIBCALL params | 1F LABEL u32
- exprs: expr, 그 뒤 바이트가 0이 아니면 계속 / params: 0=끝, 1=문자열\0, 2=expr
- expr(스택식, FF로 끝): <80 즉치 | 80 v16[u8] | A0 sys16/배열16 | C0 배열8 | E0..F0 연산자(+ - * / % rand && || & | ^ < > <= >= == !=)
  F1 imm16 | F2 imm32 | F3 flag[u16] | F5 flag[pop] | F6 m32[u16] | F7 m32[pop] | F8 v32[u8] | F9 sys32/배열32
- 메모리 배치: +0x80 flag(8bit), +0x1084 v16, +0x10EC v32, +0x1154 sys32, +0x2000 m32
- 검증: 123개 파일 전부 끝까지 파싱, 모든 점프·라벨이 명령 경계에 일치. `tools/mesdis.py`
- 연산자 E0..F0의 의미는 AI5 계열 통상 배치를 가정한 것(개별 확인 전)

## GCC (이미지) — `tools/gccdec.h`
- 헤더: sig[4], x, y, w, h (u16), u32 알파비트 오프셋, u32 색상 바이트스트림 오프셋
- n 변종은 0x14부터 데이터, m 변종은 0x14에 마스크 헤더(x,y,w,h,u32) 후 0x20부터 데이터
- G24: LZSS → BGR24 하단부터, 행 4바이트 정렬
- R24: 65535바이트 블록 단위. 블록 플래그 1 = (MTF 16칸×2 + 런 + 감마 부호) → 역 BWT(앞 2바이트가 인덱스),
  0 = 픽셀 런/리터럴. 비트스트림은 32비트 LE 워드, LSB 우선. 감마 = 0의 개수 n, 이후 n비트(MSB 우선)
- 알파: 비트 1 = 감마 길이 런, 0 = 리터럴. 8비트 마스크, 색상과 사각형이 다를 수 있음
- 검증: R24n 166개 전부 원본 EXE 디코더 출력과 바이트 단위 일치

## 미분석
- SYS 0~29 각 기능의 실제 동작(호출 형태만 수집), DATA.ARC의 .A6/.AX(애니메이션) .BIN

## VM 동작 (EXE에서 확인한 것)
- PROCD n,@skip: procs[n] = (현재 스크립트 버퍼, 다음 명령 위치), @skip으로 건너뜀
- PROC n: 현재 위치·버퍼를 저장하고 procs[n] 실행, END에서 복귀
- LIBDEF/LIBCALL(1C/1D): 같은 구조의 별도 테이블(라이브러리 프로시저)
- 19 / 1A: procs 테이블 전체를 스택에 저장 / 복원
- JMPLBL expr: 헤더 라벨 테이블[expr]로 점프, LABEL(1F)은 4바이트 건너뛰는 표식
- SYS는 최상위 루프가 0x0D를 먼저 가로채 30분기 테이블(0x4216de)로 보냄
- sys16 기준 주소는 mem+0x10B8 (sys16[2]=플래그, [9],[10]=문자 위치, [15],[16]=글자 폭·줄 높이)

## 아직 가정인 것 (EXE 대조 전)
- GOTO/CALL의 프로시저 테이블 처리, MENUI/MENUS/1B, UTIL, MSGID(기독 플래그)
- SYS 25(이미지 로드 → sys16[1]번 서피스), SYS 11,0(사각형 복사)은 인자 모양으로 추정해 임시 구현
- sys32에 들어가는 포인터 값의 초기 배치(파일 로드 영역)

## 현재 상태
- src/: arc.c, vm.c, gccdec.h = 코어. sys_stub.c = 추적용 임시 SYS 계층(교체 예정). plat_headless.c = PC 검증용
- 헤드리스 실행으로 MAIN.MES → LIBLARY.LIB → START.MES → S01.MES 첫 대사까지 진행, 타이틀·첫 장면 프레임 렌더 확인

## SYS 계층 (2차 분석)
- 인자 슬롯: 리더 객체 +0x294부터 0x2D 바이트 간격 {u8 type, char str[40], u32 val}. 핸들러에서는 val=0x2C1+i*0x2D, str=0x299+i*0x2D로 참조
- SYS 번호 → 핸들러: 0:41db80 1:41dbb0 2:41dbd0 3:421530 4:41dc00 5:41e150 6:41e1e0 7:41e270 8:41e2b0 9:41e4b0 10:41e510
  11:41e560 12:41e5f0 13:41e790 14:41e7e0 15:41e870 16:41e930 17:41e960 18:41e9e0 19:41ea50 20:41ed40 21:41eda0 22:41ede0
  23:41ef30 24:4215f0 25:41ef60 26:41efc0, 27~29는 가상 함수 [6c][70][74]
- 시스템 객체 vtable 0x44ea28: [38]=42b920(SYS 11) [3c]=41e620(SYS 12) [40]=41e7b0(SYS 13) [5c]=421e20(SYS 21) [64]=421b30(SYS 25)
- SYS 11(sub, x0,y0,x1,y1, ...): 내부 호출은 (sub, x, y, w=x1-x0+1, h=y1-y0+1, p5..p12). sub 8~13은 게임 전용(42b920), 나머지는 기본 구현
  - sub 10: sys16[1]번 서피스의 사각형을 배경색으로 채움(41b390). 색은 COLORREF(0x00BBGGRR)
- SYS 13(p0,p1): 배경색=p0, 글자색=p1
- SYS 21: 0=창 n 생성(사각형), 1=표시, 2=숨김, 3=(인자 5개, 미확인), 4=사각형 변경, 5=조회 → v16[18]
- v16[18](mem+0x10A8)이 SYS 결과 레지스터
- 글자 출력(412bf0): (sys16[9],sys16[10])에 그리고 폭 sys16[15](반각은 절반)만큼 전진, sys16[7] 넘으면 줄바꿈(줄 높이 sys16[16]),
  sys16[8] 넘으면 (sys16[5],sys16[6])으로 복귀. sys16[2]의 0x800 비트가 켜지면 그리지 않고 글자 수만 셈. 대상은 sys16[1]번 서피스

## 글꼴
- assets/font16.bin: Noto Sans CJK JP(OFL)에서 tools/mkfont.py로 만든 16x16 4bpp 아틀라스(ASCII 95 + Shift-JIS 2바이트 영역)

## 이벤트 루프·입력 (3차 분석)
- MENUS n [EXE 0x4149e0]: sys16[21]=메뉴 n의 항목 수 → PROC 8 한 번 → 반복: PROC 9, 키0→PROC 2, 키1→PROC 3, 키2~5→PROC 4~7.
  sys16[2]의 비트 0x4 또는 0x8이 서면 종료. 대사 대기도 이 루프(LIBCALL 2 안의 MENUS 100)로 돈다
- 1B n: 메뉴 n 선택+비움, MENUI: 현재 메뉴에 항목(본문 주소) 추가 [EXE 0x4135d0/0x414900]
- 키 번호 [EXE 0x409430]: 0=Enter/좌클릭, 1=Esc/우클릭, 2=↑, 3=↓, 4=←, 5=→, 6=Shift
- SYS 18(key, want): 키 상태가 want(1=눌림, 0=뗌)와 같으면 v32[18]=1 (스크립트 동작에서 도출, EXE 미대조)
- SYS 7/SYS 18 등의 결과는 v32[18](mem+0x1134), SYS 21,5와 SYS 27 조회는 v16[18]
- SYS 12 [EXE 0x429260]: p0 틱 대기, 키6으로 중단. 틱 길이는 미확인(1/60초로 가정)
- SYS 19 [EXE 0x405ec0]: 백로그(66칸×0x80C바이트). 1=항목 시작, 2=확정, 3/4=조회, 6=별도 처리. 아직 미구현
- SYS 27: 설정값 조회/저장(AI5WIN.INI 대응). 0=조회→v16[18], 1=저장 (추정)
- 대사 창: 글자는 6번 서피스의 (0,0)~(639,87)에 그려지고, 창 0(화면 0,376~640,464)이 그 영역을 보여 줌.
  합성 방식(반투명 검정 + 글자)은 추정 구현. sys16[106] 이상은 sys32 영역과 겹치는 스크립트용 임시 공간

## 그래픽 연산 (4차 분석)
- 서피스마다 색 평면(+0xC)과 8비트 마스크 평면(+0x14)이 있음
- SYS 11 기본 표 [EXE 0x420a70, 표 0x420e58]:
  0 = 색 복사(41ae60) / 1 = 색상키 복사(41af20, 키=sys32[9]) / 2 = sys16[1] 서피스를 배경색으로 채움(41b390)
  3 = 41b8a0 / 4 = 41b420 / 5 = 41b700 / 6 = 41b540 (스크립트에서 안 씀, 미구현)
  7 = 원본 마스크로 알파 합성(41b640→41b310, 0=건너뜀 255=복사, 그 외는 16MB 블렌드 표 0x462518)
- 게임 전용 표 [EXE 0x42b920]: 8 = 색 복사 + 마스크 복사(41b130) / 9 = 색상키 복사 + 41b1d0 / 10 = 채움 + 마스크 0으로(41b040)
- 스크립트가 실제로 쓰는 건 0, 1, 2, 7, 8, 10
- 글자 출력은 색 평면에 글자색을 쓰고 마스크를 올리는 방식으로 구현(원본 글꼴 그리기 함수는 미대조)
- 이미지 로드: m 변종은 마스크를 마스크 평면에 넣음. n 변종의 마스크 처리(255로 채움)는 추정

## 애니메이션 (5차 분석)
- .AX (LZSS): u32 스트림 오프셋[320] (슬롯 10 × 스트림 32), +0x500부터 그리기 레코드(7×u32), 그 뒤 스트림 바이트코드
- 그리기 레코드: (type, sx, sy, w, h, dx, dy). 원본은 1번 서피스, 대상은 0번(화면)
  type 0 = 복사(40f810→41ae60), 1 = 초록(0x00FF00) 색상키 복사(40f880→41af20), 2 = 40f670, 3 이상 = 40f940 (2·3·4는 미구현)
- 스트림 명령 [EXE 0x40f320, 틱마다 스트림당 명령 1개]:
  00 없음 / 01 n = 정지 요청 확인 후 n틱 대기 / 02 n = n틱 지연 / 03 = 처음으로 / 04·FF = 종료
  05 n … 06 = n회 반복(0이면 무한) / 07 n … 08 = 두 번째 반복 / 그 외(09) n = 그리기 레코드 n 실행
- 상태: 0=실행, 1=정지 요청(다음 01에서 멈춤), 0xFF=정지
- SYS 3 [EXE 0x41fc20]: 0=초기화(슬롯, 스트림, 데이터 주소) 1=시작 2=정지 요청 3=즉시 정지 4=재생하고 끝날 때까지 대기
  5=같되 키1로 취소 가능 6=전체 정지 요청 7=전체 즉시 정지 8·9=일시정지 계열(미구현)
- SYS 8,0,'파일',주소: DATA.ARC 파일을 풀어 메모리 주소에 적재. sys32[n]의 초기 주소 배치는 임의로 정함(원본 값 미확인)
- .A6 (LZSS): 애니메이션이 아니라 클릭 영역 표. 10바이트 레코드 {u8 id, u8 group, u16 x0, y0, x1, y1}, FF FF로 끝
- 틱 주기는 미확인(프레임당 1틱으로 가정). 서피스는 로드한 이미지 크기에 맞춰 커짐(애니메이션 시트가 480보다 김)

## 선택지 메뉴 (6차 분석)
- 메뉴 화면·하이라이트·마우스 판정은 전부 LIBLARY.LIB(LIBDEF 5)가 스크립트로 처리. 엔진이 제공할 것:
  - MENUI id,@skip: 현재 메뉴에 항목 추가(본문 = 항목 글자 TXT + END)
  - MENUS: sys16[21]=항목 수, sys32[7]이 가리키는 배열에 항목 본문 주소를 채움
  - SYS 14(주소): 항목 본문을 END까지 실행(항목 글자를 현재 커서 위치에 그림)
  - SYS 16(n): n번째 항목의 id를 sys16[22]에 기록 → 스크립트가 v16[18]=sys16[22]+1로 결과 반환
  - SYS 2: 2=포인터 위치를 sys16[3],[4]로 읽기, 3,x,y=포인터 이동(십자키 조작용)
- 메뉴 그림: 6번 서피스의 0~87행(보통), 88~175행(강조1), 176~263행(강조2)에 세 벌 그려 두고,
  376행 아래로 복사해 창 1로 보여 줌. 창 0은 6번 서피스의 왼쪽 위, 창 1은 화면 좌표 그대로(스크립트 동작에서 도출)
- SYS 21,3,n,x,y,w,h는 화면 갱신 요청으로 판단(별도 버퍼 없음)
- 위 SYS 2·14·16의 의미는 스크립트 흐름에서 도출한 것으로 EXE 미대조. UTIL 4·5·6은 미구현

## UTIL·전환 효과 (7차 분석)
- UTIL(명령 0x12)은 게임 전용 리더 vtable(0x44e9b0)의 [0x70] → 0x42b440 → 0x411330에서 11분기:
  0=40ffa0(화면 오프셋, 흔들림) 1=4102d0(크로스페이드) 2=40ffe0 3=410e00 4=410460 5=410010 6=4109a0
  7=410a30/410b90 8=4110f0 9=410150 10=42cf20/42bf40(결과 → v16[18])
- UTIL 0,x,y: 표시 오프셋 지정 후 전체 갱신. 스크립트는 0, ±4, ±8을 번갈아 넣어 화면을 흔듦
- UTIL 1,src,x,y,w,h: src 서피스의 사각형을 화면에 크로스페이드. 원본은 화면을 11번 서피스에 백업하고 15ms 간격으로
  알파를 올려 0x100에서 끝낸 뒤 일반 복사. 단계 크기는 미확인(16으로 가정). 구현은 백업을 별도 버퍼에 둠
- UTIL 3·4,x,y,w,h,src,param: 라이브러리의 화면 전환(LIBDEF 21)에서 종류별로 호출. 내부 미대조, 둘 다 크로스페이드로 대체
- 참고: 시스템 vtable [0x70]=406bd0은 UTIL이 아니라 SYS 28(창 메뉴 상태 명령)
- 미구현: UTIL 2, 5~10, 애니메이션 그리기 유형 2·3·4

## 3DS 백엔드 (platform/3ds)
- 상단: 장면(0번 서피스+흔들림)을 2×2 평균으로 320×240에 축소, 400 폭 가운데 배치. 대사 창은 상단에 겹치지 않음
- 하단: 6번 서피스 0~87행에 그려지는 글자를 문자열로도 모아(sys_ui_text) 16px 글꼴로 다시 배치(전각 20자 폭)
  선택지는 줄마다 항목 번호를 갖고, 터치한 줄의 항목 위치로 포인터를 옮긴 뒤 다음 프레임부터 확인 입력
- 입력: A/터치=키0, B=키1, 십자키=키2~5, R=키6(스킵), START+SELECT=종료
- 데이터: sdmc:/3ds/nonoxp/ (ARC 5개 + font16.bin), 로그는 같은 폴더 log.txt
- 툴체인 없이 작성. 가짜 헤더로 문법 검사만 통과한 상태(실제 빌드·실기 미검증)

## 이미지 로드 (8차, 실기 피드백 반영)
- SYS 9 [EXE 0x41e4b0 → 0x420540]: 인자 1개 = (이름), 3개 = (이름, x, y). sys16[1]번 서피스에 이미지를 올림
- SYS 9와 SYS 25는 모두 0x41ab80을 거쳐 올린 사각형을 sys16[17]=x, [18]=y, [19]=w, [20]=h에 기록
  → 캐릭터 합성 루틴(LIBDEF 13)이 이 사각형으로 3번 서피스(캐릭터)를 배경에 알파 합성하고 크로스페이드
- 위치 인자: 색 사각형은 파일 좌표 + (x,y), 마스크 사각형은 (x,y)에 배치. n 변종은 마스크 평면을 건드리지 않음
- SYS 25의 이미지 캐시(0x41f430)는 재현하지 않음

## 사운드 (9차)
- SYS 5 음악 [EXE 0x4072e0 → 0x41fdd0]: (0,이름,채널)=재생(같은 곡이 이미 재생 중이면 유지) / (1,채널)=정지 / (2,채널)=페이드아웃
  (3,이름,채널)=예약 / (4,채널)=예약곡 재생 / (5,채널)=재생 중 여부 → v32[18]. 게임 쪽은 BGM 감상용 "들음" 플래그도 기록(미구현)
- SYS 6 효과음 [EXE 0x4200b0]: 0=재생 1=정지 2=페이드아웃 3=재생 중 여부 → v32[18]
- SYS 7 음성 [EXE 0x42bce0 → 0x420270]: sys16[2]의 0x100 비트가 없으면 무시. (2,이름,ch)=예약, (3,ch)=예약 음성 재생(대사 출력 루틴이 부름),
  (0,이름,ch)=즉시 재생, 1=정지, 4=재생 중 여부. 키 7이 눌려 있으면 0·3에서 재생 취소. 설정 Voice.IsVoice/Volume 반영
- 음악 WAV(44.1kHz 스테레오) 22곡은 smpl 청크에 반복 구간이 있음. 효과음은 22kHz 모노
- SOUND.ARC(tools/mksound.py): MUSIC.ARC의 WAV를 같은 이름의 Ogg Vorbis(q3)로 바꾼 아카이브. 항목 = "AI5S" + 반복 시작/끝 + 샘플레이트 + ogg.
  263MB → 18MB. 엔진은 SOUND.ARC를 먼저 찾고 없으면 MUSIC.ARC의 WAV를 그대로 재생
- 3DS(platform/3ds/snd_3ds.c): ndsp 8채널(음악 2, 효과음 4, 음성 2), Tremor로 메모리에서 디코드, 4ms 주기 작업 스레드. dspfirm.cdc 필요

## 세이브/로드 (10차)
- SYS 4 [EXE 0x406160 → 0x41dc30]. 파일 = VM 메모리 0x0000~0x1FFF 그대로(맨 앞 0x80바이트 = 현재 스크립트 이름). 이름 FLAGnn
  0=불러오기(메모리 복원 → sys16[2]|=8 → 저장된 스크립트를 처음부터 실행) 1=저장 2=플래그를 파일과 최댓값 병합 3=플래그만 불러오기
  4=플래그·0x1180(u16 200개)·0x1310(0xCF0바이트) 지우기 5/6=0x1180 u16 범위 불러오기/저장 7/8=0x1310 바이트 범위 불러오기/저장
  9=파일 머리에 스크립트 이름 기록. FLAG00 = 전역(기독 플래그, 0x1310의 세이브 목록 정보), FLAG01~ = 슬롯
- 포팅 변경: 슬롯 저장(4,1) 때 FLAG00에 플래그 병합(4,2)도 함께 함. 원본은 타이틀 복귀 때만 병합해서, HOME/전원으로 끄면 "로드"가 비활성으로 남음
- sys16[2] 비트 8 [EXE 0x429590]: 중첩 실행을 모두 되감고 최상위에서 비트를 지운 뒤 현재 스크립트를 처음부터 실행
- MSGID [EXE 0x411eb0]: sys32[8]=메시지 번호, 현재 스크립트 이름·장면 기록을 스냅숏. 스크립트 첫머리의 JMPLBL sys32[8]이
  헤더 표(메시지 번호 → 위치)로 저장 지점에 복귀. LABEL(0x1F)은 표식일 뿐
- SYS 24 장면 기록 [EXE 0x4211a0]: 34바이트 {u16 종류, 이름 20, u16 값 6} 최대 30개, 종류 순 정렬. 0=비움 1=종류 삭제
  2/3=SaveDataNN 불러오기/저장(u32 개수 + 항목, 저장은 MSGID 스냅숏) 4=추가 5=i번 종류→v16[18] 6=i번 이름→메모리 7=i번 값 k→v16[18]
- 엔진 초기값 [EXE 0x405780]: sys16[0]=0x1310(세이브 목록 기준), sys32[0]=메모리 시작(여기서는 0). 시작 때 mwaku.gcc를 7번 서피스에 올림
- SYS 14 [EXE 0x41e7e0]: 포인터 위치의 바이트코드를 END까지 실행(메뉴 항목, 메모리 속 메모). SYS 15: .A6 영역 판정 {u16 id,x0,y0,x1,y1}
- SYS 17: 현재 날짜·시각 6×u16(년 월 일 시 분 초)을 주소에. SYS 26: 읽은 대사 비트맵(MesSkip.dat, 0x85E바이트)
- UTIL 5 [EXE 0x410010]: 0=대사 창 닫고 선택지 창 열기, 그 외=선택지 창 닫기. UTIL 6 [0x4109a0]: 사각형 마스크를 0x80으로
- 3DS: 세이브는 sdmc:/3ds/nonoxp/save/. 0번 이외의 이벤트 루프(시스템 메뉴, 세이브/로드 화면)에서는 하단에도 전체 화면을 그리고 터치 = 그 위치 클릭

## 연출 보완 (11차)
- 애니메이션 그리기 유형 [EXE 0x40f4e7/0x40f940]: 0·5 복사, 1 초록 색상키 복사, 2 없음, 3·4 효과음 ns_se59/ns_se58(오프닝 천둥), 6 전체 갱신
- UTIL 3 [EXE 0x410e00]: (x,y,w,h,규칙,방향). DATA.ARC "%02u.bin"(640×480 바이트) 값 순서대로 10번 서피스 픽셀을 화면에 복사.
  방향 0 = 0→255, 그 외 255→1. 규칙 3은 별도 함수(0x410750, 세로줄 와이프)로 근사 구현. 원본은 단계마다 즉시 갱신 → 여기서는 프레임당 8단계
- UTIL 4 [EXE 0x410460]: 부드러운 와이프. 알파 = t − 규칙값, t = 32..352(32씩, 15ms 간격). 방향 ≠ 0이면 바로 복사
- 둘 다 마지막에 10번 서피스 전체 복사. sys16[2]의 0x2000(화면 효과)이 꺼져 있거나 스킵 키면 즉시 끝
- 시작 플래그 [EXE 0x4058c8]: sys16[2] |= 0x402 | 0x8000, DispEffect.Play=1이면 0x2000

## 이벤트 CG·CG 모드 (12차, 실기 피드백 반영)
- sys16[23] = 10 으로 초기화 [EXE 0x4058b2]. 장면은 작업 화면 10에 합성한 뒤 UTIL 3/4 와이프나 SYS 10,1로 화면 0에 보낸다. 0이면 이벤트 CG가 안 보이고 얼굴 애니만 남는다.
- SYS 10,1 [EXE 0x4206d0]: sys16[2]의 0x2 비트 해제 → 화면 0을 11에 복사 → (p1이 있으면 10을 채움) → 16프레임 동안 11에서 10으로 크로스페이드, 끝날 때까지 대기 [0x41db50].
- 명령 06 SETAC = 바이트 배열 쓰기: mem[var16[v] + i] (식의 0xC0 읽기와 짝). 07 SETA@와 같이 16비트로 쓰면 sys16 영역이 망가져 CG 모드가 무한 재시작한다.
- SYS 1 = 숫자를 전각 숫자로 출력, SYS 29 = 밀리초 → v32[18], SYS 3 서브 8/9 = 애니 일시정지/재개.
- 포트 추가: 디코드한 이미지 4개 캐시 (같은 그림을 반복해 불러도 다시 풀지 않음).

## 메시지 로그 (13차)
- SYS 19 [EXE 0x405ec0 / 0x41eaf0]: 항목 66개 × 0x800바이트. sys16[2] 0x10 비트(기록 켬)일 때 첫 글자가 항목을 열고(0x20 비트), 글자를 이어 붙이며, 19,2가 닫는다.
  0=비우기, 1=열기, 2=닫기, 3=완성된 항목 수 → v32[18], 4 n=항목 n 문자열 포인터 → v32[18], 5 n=부가값, 6=로그 보기 화면 [0x42bf40].
- 라이브러리 PROC 9가 키 9(PC 휠 업)로 로그를 연다. 시스템 메뉴 3번 항목도 19,6.
- SYS 20 ptr = 문자열 길이(반각 단위) → v32[18]. 세이브 메모 가운데 정렬과 자동 진행 대기 시간에 쓴다. 0x800 비트(세기 모드)에서는 전각 2, 반각 1.
- 3DS: L 버튼 = 키 9. 로그는 하단 화면에 표시(↑↓ 선택, ←→ 5개씩, A 음성 다시 듣기, B/L 닫기). 음성 이름 기록은 포트 추가 기능.

## 입체 3D (15차, 포트 추가 기능)
- 모든 화면 버퍼에 깊이 층(dpth)을 둔다: 0 = 배경, 1 = 인물·덧그림. 그림 불러오기·채우기 = 0, 복사 = 원본 층을 따라감,
  마스크 합성(SYS 11,7)에서 불투명도 128 이상 = 1, 색 키 복사(SYS 11,1) = 1, 글자 = 1, 애니메이션 프레임 = 밑에 있던 층 유지.
- 3DS 위 화면: 3D 슬라이더 값에 따라 배경을 눈마다 최대 4픽셀 밀어 화면 안쪽에 보이게 하고, 인물은 화면 면에 둔다.
  인물 뒤에 가려졌던 배경 자리는 같은 쪽의 가장 가까운 배경 픽셀로 늘려 채운다. 슬라이더 0이면 평면(추가 비용 없음).

- (28차) sys32[1] = 메모리 기준 + 0x100000 [EXE 0x40589f]: 불러오기 후 라이브러리가 장면 기록의 음악·효과음·그림 이름을 SYS 24,6으로 그곳에 복사해 SYS 5/6/9로 다시 재생/표시. 이름 인자가 빈 문자열이면 p3 주소의 문자열을 쓴다. 불러올 때 sys32[0]/[1]은 다시 설정.
- (29차) 이벤트 CG·타이틀처럼 덧그림 층이 없는 화면은 160x120 추정 깊이로 입체: 채도(인물) 0.55 + 윤곽 밀도 0.25 + 아래쪽 0.20, 흐림·5~95% 정규화. 그림이 바뀔 때만 다시 계산, 배경 최대 7px 안쪽·가까운 곳 최대 5px 앞.
- (30차) 일반 장면 입체: 인물(덧그림 층) 안쪽은 윤곽에서의 거리(√, 22칸에서 최대)만큼 앞으로 볼록, 윤곽 0.55 → 중심 1.0, 배경 0..0.25(추정 깊이 약하게). 1칸 흐림 후 같은 역방향 변형으로 그림.
- (31차) 배경 물체 입체: 160x120 색 영역 나누기(이웃 차 <22). 큰 영역(벽·바닥·천장)은 방 원근(가장자리 가깝게, 소실점 쪽 멀게), 작은 영역(전화기·침대·자판기·의자·화분 등)은 바닥에 닿는 아래쪽 끝이 낮을수록 가깝게. 장면 배경 0..0.5, 단독 그림은 추정 깊이와 큰 값.

## 32단계: 음영 기반 볼륨(가슴·엉덩이 입체 강화)
- build_shade: 160x120 휘도에서 소규모 블러(r=2) − 대규모 블러(r=10×2) = 빛 받은 둥근 면. 밝을수록 앞으로.
- 캐릭터(스프라이트) 깊이 = 0.5 + 0.3·√거리 + 0.45·(음영−0.5)·(0.4+0.6·거리). 윤곽선 근처는 음영 영향 약하게.
- 컷신(CG): 기존 추정 깊이에 음영을 채도 가중으로 더함 → 피부·옷의 둥근 부분이 튀어나옴.
- 앞쪽 한계 3px → 4px(슬라이더 최대).
- 32-1: 음영이 타이틀 글자까지 둥글게 만들던 문제 수정 — 음영을 넓은 형태(블러 r=4+3)만 쓰고, 글자처럼 경계가 빽빽한 곳(에지 밀도)은 음영 0.

## 33단계: AI 깊이 지도 (DEPTH.PAK)
- Depth Anything V2 (base, ONNX)로 BG.ARC의 CG·배경·캐릭터 스프라이트 151장의 깊이를 미리 계산. 생성은 비공개 저장소 CI (tools/depth/gen.py, depth.yml). 게임 그림이 들어가므로 이 공개 저장소에는 결과를 넣지 않음.
- DEPTH.PAK: "DPK1", u32 개수, 항목 24바이트 {char name[16]; u16 w, h; u32 off}, 데이터 = 그림의 1/4 해상도 8비트(255 = 가장 가까움). 스프라이트는 마스크 안에서 2~98% 정규화, 밖은 0.
- 3D 층 값: 0 배경(지도 없음), 1 스프라이트(지도 없음), 2..127 지도 있는 배경, 128..253 지도 있는 스프라이트.
  load_image가 지도를 층에 씀. 스프라이트를 그릴 때(blend/key) 2..127 → +126. 지도 없는 작은 조각(표정, 눈·입 애니메이션, 변형 패치)은 밑의 지도 깊이를 유지.
- 3DS: 캐릭터 0.55~1.0, 캐릭터가 있을 때 배경 0~0.5, 없을 때(CG) 0~0.85, CG 위 텍스트창 0.9. 지도가 없으면 예전 추정 방식.
- 33-1: 입체 강도 상향 — 슬라이더 최대에서 뒤 6.5px, 앞 5.5px (기존 4/4). 깊이 지도 블러 r=2로 통일(경계 찢어짐 방지).
- 33-2: 전환 중에도 3D 유지 — SYS 10 크로스페이드를 draw_eye_dm 안에서 같은 깊이로 섞음(전에는 페이드 동안 평면). 깊이 재계산: AI 지도 화면은 색과 무관하게 층 값만으로 서명, 계속 바뀌는 동안은 4프레임에 한 번, 외곽선 거리 계산은 지도 없는 스프라이트가 있을 때만.
- 33-3: 글자 일그러짐 수정 — (1) 지도 없는 전체 화면(안내문, 오프닝 글자, 메뉴)은 DEPTH.PAK이 있으면 평면 한 장. (2) 얇은 스프라이트(글자·로고·창)는 3칸 넓혀 평평한 판으로(획마다 깊이가 달라 휘던 문제). (3) 한글 타이틀(patch/titlelogo.gcc = OP + 로고)에 OP의 AI 깊이 + 로고 판을 넣은 항목 추가(tools/depth/add_logo.py).
- 33-4: 강도 상향 — 슬라이더 최대 뒤 9px / 앞 7px. 캐릭터 외곽 깨짐 방지: 역방향 와프 3단계(마지막은 두 깊이 평균), 깊이 블러 r=3.
- 33-5: 테두리 왜곡·캐릭터 지저분함 수정 — 3단계 와프 제거(2단계로), 좌우에 양쪽 눈 동일한 검은 창틀(최대 이동폭), 캐릭터 내부 굴곡 0.6~0.95로 완화, 강도 뒤 8px / 앞 6px.
- 33-6: 배경 대비 곡선 — 다른 AI가 만든 DEPTH.PAK 시험판(전 항목에 같은 S자 곡선)을 분석해 그 곡선을 표(bg_curve)로 옮김. 캐릭터 뒤 배경에만 적용, 캐릭터·이벤트 CG는 원래 AI 깊이.
- 33-7: 이벤트 CG 고정밀 깊이 — 전체 화면 그림 121장을 Depth Anything V2 Large로 518px(전체 형태) + 1036px(세부: 주름·얼굴·손) 두 번 계산해 합성, 1/2 해상도(320x240)로 저장(tools/depth/gen2.py, 12개 병렬 작업 + merge.py). DEPTH.PAK의 같은 이름 항목을 교체.
  엔진: 지도 크기 비율을 그림 크기에서 계산(1/4·1/2 모두). 3DS: 지도 있는 전체 화면은 320x240 깊이(g_dmh, 3x3 블러)로 와프, 깊이 폭 0~1 전부 사용.
